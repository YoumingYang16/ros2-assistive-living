# 行知 V7 · 日常生活辅助与 ROS 2 设备接入

**版本 7.0.0。** 面向行动不便成年人的居家生活，以及相关出行、工作学习和社会活动支持。提供语音与文字入口、提醒、人工协助请求、个人清单、设备维护记录和机器人动作编排，以本人选择、确认和可追溯结果为中心。本版补齐已有生活记录的对话操作、完整历史检索和提醒日历编辑。

当前目录按 **12 个领域列出 95 个场景**，对应入口已通过隔离软件验证；这是有边界的覆盖审查，不宣称穷尽所有人的生活需求。身体接触照护由人工协助流程承接，设备动作需要实际驱动和环境部署。原生 ROS 2/DDS 软件集成结果见下方 GitHub Actions；没有进行真实机器人、真实照护或实际对外通信测试。

[![ROS software integration](https://github.com/YoumingYang16/ros2-assistive-living/actions/workflows/ros-integration.yml/badge.svg)](https://github.com/YoumingYang16/ros2-assistive-living/actions/workflows/ros-integration.yml)

GitHub 工作流使用 Ubuntu 24.04 和 ROS 2 Jazzy，实际编译自定义接口并启动独立节点，检查导航、类型化观察、取消、能力接口、生命周期和服务丢失。Action 服务端使用明确标记的测试预设，因此通过表示原生 ROS/DDS 软件进程通信成立，不等于 Nav2 实际规划、传感器识别或真实机械动作已验证。具体结果以对应提交的工作流记录为准；`docs/` 中最初 Windows 本地验证报告保留原始时间与范围。

## 启动软件演示

需要 Python 3.10+。软件演示无需 ROS、模型服务或机器人硬件。

```powershell
.\start_home.ps1
```

或在项目目录运行：

```sh
python -m robot_voice_patrol --home --mode mock --fixture-skills --port 8773
```

打开 [本机生活辅助首页](http://127.0.0.1:8773)；`#mission` 为详细任务工作台。居家数据库默认 `.runtime/home.sqlite3`，原控制台数据库另存。`--fixture-skills` 明确启用软件预设设备端点；不传此项时，取放、交接和家居控制会报告能力不可用。

```sh
python -m robot_voice_patrol --home --command "十分钟后提醒我喝水"
python -m robot_voice_patrol --home --command "我需要如厕帮助"
python -m robot_voice_patrol --home --command "开始工作学习准备清单"
python -m robot_voice_patrol --home --command "报告停电"
python -m robot_voice_patrol --home --command "生成照护交接摘要"
python -m robot_voice_patrol --home --preview --command "把手机从客厅送到卧室"
```

单次 CLI 保存提醒或平安确认后即退出；到时处理需要生活辅助服务持续运行。再次启动会恢复到时、逾期和待核实记录，不伪造本人已知晓或实际活动已经完成。

## V7 三项补齐

**用语音或文字处理已有生活记录。** 可以说“确认提醒喝水”“提醒喝水稍后十分钟”“取消提醒喝水”“把喝水提醒改到明天上午八点”“我在”，也可记录协助响应、逐项完成清单和用品准备状态。若有多条同名或可处理记录，先列出候选并允许说“第一个”“第二个”；不会随机选择。会话保留有限时效的上下文，记录已经变化时旧选择不会执行。语音识别结果进入相同的文字处理链；麦克风需本人主动开启，实际识别质量仍取决于已配置的语音服务。

**查找完整生活历史。** 首页“全部生活记录”按类别、状态、关键词和更新日期筛选，每页最多 100 条，支持前后翻页、单条详情和处理历史分页。已结束、已取消及已移除记录也能查到，不受首页每类 250 条摘要限制。日期按本机日历日换算，筛选依据是更新时间；联系人地址提示和结构化凭据不通过历史接口返回。

**修改提醒和设置每周日历。** 建立提醒时可选择单次、固定间隔、每天或每周指定几天，并设置截止时间；未结束提醒可从当前列表或历史详情点击“修改提醒”。编辑采用修订号检查，遇到其他操作更新记录时要求先重新读取，防止覆盖较新的状态。固定间隔与按当地日历的重复分开处理，服务恢复后保留待确认事项，不补发一串错过的周期。截止不会把尚未确认的提醒自动记为已知晓。

主控制台和生活页共用当前标签页的对话会话。已有生活记录的预览执行绑定原记录；候选按钮显示易读名称和序号。提醒列表按钮与编辑表单都检查修订号，旧页面不能直接作用到已经改变的提醒。历史详情编辑后同步刷新，修改筛选条件后点击“查询生活记录”应用；翻页继续使用最近一次已提交的筛选。

以上三项处理的是软件任务与生活记录。导航、家居和取送仍通过 ROS 2 控制链与实际驱动对接，不因记录写入成功而认定物理动作完成。结构化调用示例见 [V7 接口与使用说明](docs/API.md)，完整日历规则见 [提醒修改与本地日历](docs/REMINDER_CALENDAR.md)，查询语义见 [生活历史](docs/ASSISTIVE_HISTORY.md)，对话示例见 [生活对话](docs/ASSISTIVE_DIALOGUE.md)。

## 已实现的生活支持

- **提醒和本人记录**：饮水、用餐、既有服药与活动安排、姿势和预约提醒；本人知晓、稍后提醒、重复与逾期处理、修改安排、每周日历和截止日期；用品需求和舒适度记录。
- **人工协助请求**：个人起居、移乘、家务、出行、阅读交流、家庭责任、照护边界和备用人员等。本机记录请求、本人报告回应和解决进度；默认没有给任何人发送消息。
- **14 套日常清单**：晨间、睡前、出门、回家、用餐、居家检查、就医、旅行、工作学习、社交、停电备用、应急撤离、个人活动和访客准备；也可创建自定义清单。逐项确认不替代实际照护。
- **异常和支持中断**：本人报告停电、网络中断、设备故障、通道受阻、人员未到、天气影响或呼叫设备不可用，关联本地人工协助记录；没有自动危险检测。
- **设备台账与维护**：登记辅助器具和设备，按本人填写的日期建立提醒，保存本人维护记录和下一次日期；没有自动检查、修理或认证设备。
- **主动平安确认**：本人主动开始一段等待，主动确认或取消；逾期创建待人工核实的本机协助记录。未响应不等于发生危险，也不会自动外呼。
- **本机交接摘要**：汇总未结束待办和未来一天内的提醒，保留来源和生成时间；默认省略联系人地址与私密历史备注，可下载，默认不分享。
- **家居与取送接口**：灯、窗帘、风扇、电视状态控制；允许物品的观察、取物、运输、放置或确认交接。具备软件参数与证据校验，实际动作依赖设备端。
- **无障碍交互**：大字、高对比度、键盘操作、可退出的单键扫描和快捷沟通文字；可选浏览器或本地 Vosk 语音接口。麦克风不自动开启，外部客户端需自行适配显示偏好。
- **任务与记录**：SQLite 持久化、请求去重、状态审计、完整历史分页与筛选、联系人和单次联系同意、可信宿主签名通信回执；原有条件任务、工作流、队列、备份、恢复评估和停止控制继续可用。

自然语言使用受约束的规则与明确句式；不保证理解任意表述。目录以外可用表单和 API 创建自定义提醒、清单、用品需求及一般人工协助。95 个场景是不同的支持入口，不是 95 种自主机器人动作。

## ROS 2 和真实设备

网页是一种输入与状态显示入口。项目还提供 Python/CLI、ROS 2 生命周期任务节点和 `/voice_patrol/command` 文字命令话题；可关闭网页继续运行任务节点。

已有 `Ros2Adapter` 真实 Action 客户端代码，V6 新增 `HardwareGatewayNode` 的 `ExecuteSkill` ActionServer 和 `GetCapabilities` 服务。通用技能网关可从本机启动配置加载可信 `module:factory` 驱动，检查参数、终态证据和传感器回读，保存去重回执；设备状态未知时阻止后续动作。未配置驱动时不声明硬件能力。

部署方仍需提供厂商设备驱动、Nav2/定位/地图、物品感知，以及机械臂抓取与设备控制实现。接口和驱动装载机制已经编写，不表示这些外部系统已经部署或在真实硬件上验证。

```sh
ros2 launch robot_voice_patrol home_hardware.launch.py config:=/absolute/path/home.json provider:=my_robot_driver:create_driver hardware_journal:=/absolute/path/hardware-receipts.sqlite3
```

`my_robot_driver:create_driver` 是待集成的可信驱动工厂示例，不是附送的厂商驱动。需要先在 ROS 2 环境构建接口包，并使用真实家庭地图和稳定、独立的硬件回执数据库。完整契约和取消/未知状态处理见 [ROS 2 与真实设备的控制链](docs/HARDWARE_GATEWAY.md)。
