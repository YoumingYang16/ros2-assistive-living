# 队列、历史和数据恢复

## 调度

队列页面支持文字任务或工作流、优先级、指定时间和周期。已到期任务先比较优先级（100 最高），同优先级按时间排序；运行中的任务不会被高优先级任务抢占。单个服务只有一个动作资源，队列不会并发移动。

自然语言支持延迟、每日、间隔和当前任务结束后执行。具体样例见 NATURAL_LANGUAGE.md。每日时间默认 Asia/Hong_Kong；HTTP 的 run_at 必须含时区。interval_seconds 为 1 秒至 365 天，daily_at 为 HH:MM 并指定 IANA 时区。每日重复遇夏令时使用 fold=0；不存在的本地时间经时区往返规范化。间隔任务以原计划时间为锚点，跳过已错过周期。

任务提交后存入 SQLite。服务必须持续运行才能按时派发，应用不会创建操作系统计划任务。重复任务保留最近 50 次执行引用，完整任务仍保存在历史中。最多 500 个活动队列条目。

队列暂停只阻止后续派发。停止当前任务使用任务“停止”或取消正在运行的队列条目，此操作也暂停队列。恢复服务时，历史中断任务保持 interrupted，等待任务保持暂停，重复任务不会突发补跑。修改配置后旧队列任务会 blocked，应重新预览并提交。

## 历史记忆

历史页面可按原文、状态、时间和归档状态筛选，详情与导出保存步骤结果和来源。记忆页面进一步查询物体、地点与观察结论。

“上次在哪里发现水杯”“水杯上次在哪里”“今天哪些地方检查过”“上次实际到达哪里”使用已保存的执行证据。超过一小时的观察标为陈旧；任何历史记录都不代表物体此刻仍在原处。“去最近一次发现水杯的地方”生成待确认草稿，并附上记录来源和时间。

## 从任务中断恢复

1. 在历史中选择 interrupted、failed 或 cancelled 的任务，生成恢复预览。
2. 系统检查当前执行器是否空闲、外部动作是否已确认结束，并展示核对依据。
3. 已完成、跳过或明确处理完的失败步骤保留为历史证据。只为剩余步骤生成新计划；历史到达不能证明当前位置，必要时会先重新导航。
4. 核对计划后确认，创建带 parent_mission_id 的新任务。原记录保存 resumed_as，不会覆盖原失败证据。

恢复不是自动续跑，也不会把“无法判断”当作“未找到”。如果 ROS 目标 UUID 缺失、远端仍运行、状态未知或状态历史已经过期，将阻塞恢复。不能通过点击确认跳过此核对；应由实际接口实现可靠的远端状态查询。

未发生派发的队列条目在队列中恢复；已经中断的执行任务从任务历史生成恢复计划。恢复新任务不会自动重新启用原周期调度，应核对后重新建立周期任务。没有剩余步骤时只返回核对提示。

## 备份与恢复

备份使用 SQLite backup API 获取一致性快照，不直接复制正在写入的数据库文件。每份备份包含 SQLite 文件和 SHA-256 清单，存入数据库同级 backups 目录。控制台可以创建、验证和下载；接口只接受备份 ID，不接受任意路径。

网页“准备恢复”只验证并登记待恢复备份，不替换正在使用的数据库。真正恢复时先关闭占用原数据库的服务，再执行：

```bash
python -m robot_voice_patrol --db .runtime/missions.sqlite3 --restore-backup backup-完整ID
```

命令取得同一排他锁后再验证，自动备份恢复前的数据，然后恢复并迁移数据库。重新启动后队列保持暂停。若其他进程仍占用数据库，恢复会拒绝。普通重启不会执行已登记的恢复操作。

从其他电脑迁移时，在控制台同时下载 SQLite 备份和校验清单，并把它们放入目标数据库同级的 backups 目录；目标数据库路径必须存在。只下载 SQLite 可用于离线分析，但恢复校验还需要同 ID 清单。:memory: 模式不能创建持久备份。

## 归档策略

归档是可逆状态变化，不物理删除证据。先预览匹配条数，再按时间和终态筛选执行；待恢复记录不会被自动归档。历史切换到归档项后可撤销归档。

默认保留策略为 90 天，自动归档关闭。开启后，服务每 60 秒检查一次已完成任务。保留天数允许 1–36500。请求回执与观察证据仍保存，以便审计和去重；需要长期空间管理时可以先备份再按业务规则扩展物理删除流程。

## 修改等待任务

队列页面“调整待执行任务”可以修改优先级、新执行时间和重复策略。修改只适用于 queued；任务已派发时拒绝，不会改变正在执行的动作。API 为 `PUT /api/queue/{id}`，接受 priority、run_at、repeat，至少一项。run_at 必须是带时区 ISO 字符串；repeat:null 改为单次；未指定 run_at 时保留当前首次到期时间。所有修改带修订号及修改前后值写入事件日志。
