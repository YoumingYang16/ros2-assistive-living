# V4 审查与改进记录

本次以 V3 为基线，先复现并修复边界问题，再增加直接服务无硬件开发的验证工具。未以复制模块或第三方依赖增加代码量。

## 修复的执行与持久化问题

1. 调度草稿现在与对应任务绑定。解析失败不会先落盘调度意图；无关的新任务不继承前一草稿的定时信息。预览与发送使用相同的调度解析。
2. 排队计数和派发扫描覆盖完整的 500 项活动队列限制，不再被默认的 200 项展示限制截断。
3. 任务就绪检查、配置指纹检查与实际派发串行化，避免人工提交或配置更新恰好插入检查与派发之间。
4. 停止指令与动作成功同时发生时，先保存已经完成的动作证据，再终止任务；恢复不会重放刚完成的步骤。
5. 恢复任务创建与原任务关联在同一事务内完成。同一父任务不能使用新的请求 ID 再恢复一次；并发重复确认返回同一回执。
6. 队列任务已经结束但调度记录尚未刷新时，取消该条目不会误停后来启动的人工任务。
7. 恢复选择器同时展示中断、失败和取消的记录，并排除已生成恢复子任务的记录。

上述问题由 tests/test_reliability_v4.py 的 18 项针对性回归覆盖，并与既有测试联合运行。

## 新增能力

- **场景验证台**：六种可重复的成功、未知和失败情况；隔离执行与真实执行器共用状态机；比较报告、证据详情和 JSON 导出；同时支持 CLI。
- **执行前检查**：能力和生命周期、当前任务占用、草稿确认、配置变化、位置保证、重试次数与配置超时预算。
- **调度修改**：只允许修改尚未派发任务的优先级、时间和重复策略；旧值、新值、条目 ID 和修订号写入审计事件。
- **UI 一致性**：场景载入请求合并，防止重复生成选项；编辑输入后旧报告失效，运行期间锁定输入。

## 兼容与边界

应用版本为 4.0.0，默认端口为 8768。数据库结构仍为 schema 3，编译计划仍为 version 3，工作流 DSL 仍为 version 1；没有仅为版本号引入无必要的数据迁移。V2/V3 数据和计划继续兼容，但同一个数据库仍不能由两份服务同时打开。

ROS 原生运行仍受当前 Windows 策略限制。本轮不声称验证真实 DDS、colcon、容器、硬件或语言模型推理。场景运行的加速时间也不能作为真实机器人任务耗时。

本轮停止扩展的依据是：已发现的关键竞态和持久化问题有修复及回归，新旧软件功能联合测试通过，网页和安装包可运行。未来增加真实设备、感知模型或新的部署约束时，仍需要针对相应条件重新验证。
